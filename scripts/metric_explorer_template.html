The headline result, and where it stops holding

The loss-space effect is unambiguous for MOMENT and absent for TimesFM. Both were trained on the same corpus, the same window index, and the same schedule, so the difference is in the objective, not the data.

modeltasknormalized wins (MASE) median ratioMASE Gini, norm vs orig
MOMENT masked reconstruction — target inside the context 42 / 420.414×0.163 vs 0.369
TimesFM forecasting — target outside the context 11 / 421.090×0.407 vs 0.456
Read this as a boundary condition, not a contradiction. For MOMENT, normalized-space loss wins on every single dataset and more than halves cross-dataset inequality. For TimesFM the same comparison is a coin flip that mildly favours original space (median ratio 1.09×), and the Gini gap shrinks to 0.407 vs 0.456. Any claim that normalized-space loss is universally better is not supported by these runs; what is supported is that it is decisively better for the reconstruction objective and neutral-to-slightly-worse for this forecasting objective.

The most likely mechanism is where the target sits relative to the normalization statistics. MOMENT reconstructs positions inside the window RevIN normalized, so the target is always on the same scale the loss is measured in. TimesFM forecasts beyond the context, normalized by the first patch only, so the target routinely sits off that scale — which both weakens the benefit of normalized-space loss and is the same structural fact that made the degenerate windows ill-posed. This is a hypothesis the current runs motivate but do not test.

Why TimesFM breaks, and what a faithful fix looks like

Recorded here because the fix has to keep TimesFM close to its released behaviour rather than quietly re-engineering the model.

TimesFM normalizes by the first patch, not the context

_masked_mean_std in the vendored decoder states it directly: "We return the statistics of the first patch with more than three non-padded values." So μ and σ come from the first 32 timesteps, not the 512-step context, and σ is then clamped: sigma = clamp(sigma, min=tolerance) with tolerance = 1e-6.

A series that merely starts flat therefore gets σ ≈ 0 even when the full context varies. This is why filtering on the window index's context_std is the wrong test: it flags only 6,609 of 41M windows (0.016%), because it measures the whole context rather than the statistic TimesFM actually divides by.

conditionwhere the loss is computedeffect of tiny σ
timesfm_native_original after _reverse_transform σ cancels — released behaviour, healthy
timesfm_normalized before the inverse transform target divided by σ → values to 1e9, loss to 3e17
The pathology is not in TimesFM. The released model computes its loss in original space, where the clamp is harmless. The normalized-space condition is our addition for this study, and it is the thing that is ill-posed when the first patch is flat. So the fix belongs on our side of the boundary, not in the vendored file.

Fix, as implemented: forward flags degenerate = sigma <= tolerance × (1 + 1e-6) using TimesFM's own statistic; training_step_metrics drops those windows from the loss, and both reported metrics return NaN for them so the existing NaN-dropping aggregation removes them. The vendored decoder is unchanged at its pinned revision, and the clamp and first-patch convention are preserved. The same exclusion applies in both loss spaces, so the variants stay paired on identical windows.

Verified in flight. A 60-step smoke run returned final_pooled_mse = 289.5 against 1e12+ before. In the refreshed 30k-step runs, eval/pooled_mase reads 2.85–4.12 against 7230.5 in the broken variants, and pooled nMSE 101–176 against 1.06e12.

Is the MOMENT result a learning-rate confound?

Both MOMENT variants trained at lr = 1e-4 with grad_clip_norm = 1.0, and no learning-rate adjustment was applied to the original-space variant. Measured on identical batches from a fresh init:

variantmedian grad normfraction above the 1.0 clip
moment_normalized8.83e+011.00
moment_original2.92e+101.00
Both variants are clipped on every step. Each update is rescaled to norm exactly 1.0, so the variants already take steps of identical gradient magnitude — the runs are the unit-norm gradient-matched control. What clipping cannot equalize is gradient direction: within a batch, original-space loss weights high-magnitude datasets far more heavily. So the sweep is a directional effect, not a step-size artifact, which is what the synthetic study's own grad-matched control predicted.

The same reasoning is why no learning-rate sweep is planned for the natural mixture. In a controlled experiment b is imposed, so the correction bp is known. In natural pretraining every dataset carries its own bd, so the required correction is not a scalar. One global learning rate can absorb one global factor; it cannot undo per-source heterogeneous rescaling.
